## Functional details and corrections

Calendar is a read-only presentation of the active workspace's actual uncompleted tasks/milestones and application interview/deadline/follow-up dates. Closed/rejected/withdrawn applications are omitted. Prev/next month controls preserve keyboard focus; today is highlighted and dated items are announced. Links lead to the existing record sections. It does not create reminders, persist a new data format or claim closed-browser notification delivery.

Visual QA caught an inherited `grid-column: 3` on schedule creating three narrow implicit rail columns; the rail now explicitly resets child placement. Contrast checks caught old first-metric white text after its surface became white; foreground now follows theme tokens. A responsive test's old lead-grid selector was updated to the new workbench container without dropping the assertion; a new desktop geometry regression ensures full-width, vertically stacked rail cards.

An inherited global mobile table-to-card rule also affected the new calendar and comparison tables. It is now scoped to the application table wrapper; mobile calendar regressions verify seven columns and bounded height at 375/768px. Existing tracker card semantics remain.

The full suite also exposed an outdated keyboard-wrap expectation after adding the Compare plans link: the final focusable control is now that link, not the previous billing nav button. The assertion is retained against the current last control. The drawer delegate now includes internal navigation links so selecting Compare plans closes it even on the already-active billing route; explicit regression steps cover both route changes and repeated selections.

No Auth SDK, RLS SQL, workspace storage, webhook, billing backend, canonical prices, age/consent checks, entitlement decisions, secrets or approval flags changed in this refinement. Existing authentication and payment tests remain enabled.
