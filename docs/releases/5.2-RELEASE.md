# Launchpad 5.2 — release evidence

Follow-up: the supplied logo/reference refinement is documented in [the current brand report](5.2-BRAND-REFINEMENT.md). The original test evidence below belongs to commit `2575f22`; current execution is recorded in that report.

Date: 28 October 2026. Branch: `feat/launchpad-5-2-commercial-experience`.
Base: integrated 5.1 commit `64a3354962aab530e24c3aaaaad72f43a698e92c`.
This is a reviewable commercial release candidate, not an activated paid service.
No merge, deployment, secret change, migration execution or billing/legal flag activation was performed.

## Implemented

- Re-composed dashboard: original career-studio illustration, career compass, colored metrics, progress/coach/momentum bento, recent applications, interview/deadline schedule and contextual next action. All numbers derive from actual workspace records; empty states do not invent activity.
- Richer light/dark design tokens, navy navigation, responsive forms, career journey, company favorites, analytics and settings. Existing mobile drawer and keyboard behavior retained.
- Auth story panel, labeled password visibility controls, signup/reset requirements and confirmation feedback, pending states. Fixed a CSS specificity bug that displayed hidden signup consents during sign-in. Supabase remains the authentication authority.
- One workspace snapshot drives account/guest labels. Fixed an asynchronous race: a failed save from the previous account could overwrite the new guest workspace status. Errors still propagate to the caller; private records do not transfer.
- Application search has an explicit search identity and autofill hints; it never clears a deliberately entered email-like query. App-driven copying of an Auth email was not reproduced, so browser autofill is a possibility, not an established cause.
- Job discovery: title/company/location/skills/text experience/category filters, provider-reported arrangement, salary-present filter, sorting, progressive 12-item pages and sourced cards. Filters operate on the returned cached pool (up to 100), not every worldwide job. Missing salary/country/experience is not fabricated.
- Workspace-owned job bookmarks, explicit guest bookmark import, deduplication and JSON preservation. Ten is the new-bookmark UI cap; existing imports above that remain readable. Source availability may have changed. Tracker country defaults to Other for review instead of guessing from search text.
- Billing: canonical prices unchanged, plan comparison, honest checkout-method disclosure, verified-plan state, safe operation activity and an explicit provider transaction-history request. New Sandbox-only backend endpoint checks customer ownership, rate limits requests, strips payment/card/checkout details and cannot grant entitlements. No-customer responses state that Paddle was not contacted.
- Remotive normalization now carries provider category, employment type and remote-only endpoint provenance. Existing cache/abuse controls retained. Unsafe external URLs are rejected.
- Analytics safely handles literal company names such as `__proto__` and `constructor`.

## Test evidence

Clean `npm ci`, `npm run build`, `npm run build:check` and complete `npm test` were executed with Node 24.19.0, Linux and Chromium 154. **All 161 tests passed, with zero failures:** 94 source browser + 13 production browser + 47 backend/model + 3 SQL files + 4 build/config. `npm audit` reported zero vulnerabilities. `check:staging` returned NOT VERIFIED for all four public checks; `test:live` returned NOT RUN because secure test-account bindings were absent. The suite comprises 94 source-browser cases, 13 built-site cases, 47 backend/model cases, three PostgreSQL/PGlite test files and four build/config cases. Function bundle and dependency-pin checks also run.

New regressions cover stale workspace failures, consent visibility, password controls, bookmark migration/isolation/import above UI cap, pagination/filtering, truthful billing state, owned provider history, foreign-customer/live-environment rejection and prototype-like analytics names. The workspace race was reproduced failing before the fix, then passed after it.

Browser tests exercise light/dark contrast and accessibility scans, responsive layouts, Auth flows with deterministic network fixtures, applications CRUD, roadmap/tasks/reload/JSON recovery, mocked account switching/cloud synchronization, jobs, AI consent and billing. SQL tests exercise migrations and RLS locally through PGlite; they do not establish the deployed database's configuration. Automated accessibility checks do not certify WCAG compliance or replace physical screen-reader/device review.

## Security, data and brand limits

No passwords are stored manually. Existing RLS, account ownership, server entitlements, age/consent checks and simulation-event protections remain. Guest records, backup keys and SQL migrations are preserved. Public builds contain no server functions, SQL, environment files or documentation. The default artifact intentionally remains guest-only until public Supabase configuration is supplied during build.

At the initial `2575f22` milestone, no new official logo or external design-reference files were attached. This historical limitation is superseded by the follow-up brand report. The existing Launchpad mark/favicon remains, rather than replacing it with an invented generic mark. The new illustration is original and is not a logo. Faithful logo vectorization, light/dark/mobile brand variants and reference-image comparison remain blocked pending those files. Existing employer marks retain their documented provenance; trademark/legal review remains necessary.

**Recommendation: GO for code/design review and controlled local testing; NO-GO for paying customers.** Real email, database isolation, jobs, payment lifecycle, staging, operator/legal approvals and supplied-brand review must pass first. The 15 November target does not waive those gates.
