# Launchpad 5.8 — Windows CMD, local preview and Staging

No website publication, merge, paid resource, secrets or billing approvals were changed.

## Update and verify

Export JSON from important workspaces first. Save any code changes before switching branches. Do not discard them with `reset --hard`.

CMD, with Git and Node 24 installed:

```bat
cd launchpad-career
git status
git fetch origin
git switch feat/launchpad-5.8
git pull --ff-only
set PUBLIC_SUPABASE_URL=
set PUBLIC_PUBLISHABLE_KEY=
set REQUIRE_PUBLIC_AUTH_CONFIG=
npm ci
npx playwright install chromium
npm run build
npm run build:check
npm test
npm run audit:public
```

If the branch is not local, use `git switch --track origin/feat/launchpad-5.8` after fetch. These public `set ...=` values only affect this CMD window and deterministic builds, not remote settings.

Local source preview (guest mode):

```bat
npm start
```

Open `http://127.0.0.1:8000/`. Stop with Ctrl+C. The source preview does not inject build-only Auth configuration and is not a proof of live authentication.

## Fresh configured Staging build

Use only the existing project’s **public** publishable/anon key, never service_role, `sb_secret`, SMTP, AI or Paddle secrets.

```bat
set PUBLIC_SUPABASE_URL=https://oyatshlhqdxosvbelsvp.supabase.co
set PUBLIC_PUBLISHABLE_KEY=PASTE_ONLY_THE_PUBLIC_PUBLISHABLE_KEY
npm run build:staging

```

The build recreates `_site`. Confirm `build-manifest.json` has **88 public files**, correct hashes and `publicAuthConfigured: true`. A blank-config guest artifact does not connect to your project. If running tests afterward, regenerate Staging before any upload.

Cloudflare Direct Upload does not inject dashboard variables into files already built locally. Public values must be supplied at build time. Never upload source backend, SQL, tests, `.env`, credentials or `node_modules`.

## Backup and rollback

Existing saved applications, resumes, tasks, goals and preferences continue in their existing storage and JSON format. Recently viewed jobs are session memory only; they are not included in JSON backups and clear on reload/workspace change. Demos save nothing.

Rollback frontend through the previous Cloudflare deployment after retaining JSON exports. No database rollback is required. Never restore an old database over newer user records automatically. Guest data is origin-specific; changing domains requires explicit export/import. Protect backups as personal data and verify the Supabase plan’s backup/PITR retention before commercial operation.
