# Launchpad 5.3 — Jobs & Auth Polish RC

28 October 2026. Branch: `feat/launchpad-5-3-jobs-auth-polish`.
Base: `feat/launchpad-5-2-commercial-experience`, commit `8985e39`.

Implemented in the existing HTML/CSS/JavaScript, Supabase and Edge Function architecture. No merge, Cloudflare/GitHub Pages deployment, SQL execution, credential change, legal-approval change or payment activation is included.

## Delivered functionality

- Premium Job Explorer: dedicated keyword search, advanced title/company/region/skill/category/reported job-type/arrangement and salary-present filters; removable filter chips; clear filters; source/newest/company sorting; progressive loading. Desktop filter rail, accessible mobile Filters toggle, compact listing rows and local employer marks/fallbacks.
- All/Saved/Tracked collections share actual active-workspace data. Search and tracked matches operate on the returned source pool, not a worldwide exhaustive database. Experience remains a clearly labeled title-text match. Missing salaries, countries, benefits, experience, match scores and hiring status are not guessed.
- A functional Job Details screen at `#jobs?job=<encoded-source-key>`: provider description, source facts, safe external application link, bookmarks, save to tracker, keyboard tabs, provenance and curated employer website where available. Back to results retains filters and restores focus. Unloaded/expired/unsaved deep links offer explicit retrieval; URL fragments cannot choose a backend URL.
- Source HTML is converted by a bounded forward-only server tokenizer to inert text. Headings/list presentation comes from the actual text. Browser rendering uses text nodes, not provider HTML. Embedded markup/URLs never become executable elements. Descriptions are capped at 24,000 characters and visibly marked when truncated; original source remains accessible.
- Bookmarks store at most 1,200 UTF-8 bytes of description each, with an excerpt flag and original link. A 44 KB serialized preference guard leaves room below the existing 50 KB database bound. Existing bookmark records/preferences are preserved; a full preference row rejects an addition with an actionable message. Explicit guest bookmark import and JSON backup/restore remain.
- Auth: refined brand story, tabs, readable forms and primary actions, contextual subtitles, inline error styling, accessible invalid-field/error associations, existing password visibility and 12-character requirements, consent/age validation before requests. Missing consent no longer erases an otherwise valid in-memory password; closing or completing an Auth request still clears passwords as before.
- Four truthful setup stages: Account → Confirm email → Personalize → Ready. Signup requests remain pending until actual server confirmation. Personalization uses existing profile/goal forms and only the loaded account's saved progress. Guest progress never marks a private account complete. Profile/goals are optional and cloud roadmap editing follows existing plan limits.
- Existing email/password sign-in, PKCE confirmation, resend, recovery/reset, sessions, logout, deletion, explicit guest migration and billing protections retained. No social buttons were introduced: OAuth was not configured or verified.

## Bugs found and fixed

The first integration pass exposed a signup/recovery visibility regression; the existing narrow-screen recovery test was kept and the control restored. Local consent validation was moved before the asynchronous request so validation errors do not clear the password. Populated dark-theme testing exposed a transient contrast failure: outline-button background animation lagged behind theme text changes. Surfaces now switch with the text while focus/transform/border feedback remains.

New regressions verify description safety, malformed input bounds, UTF-8 bookmark budgets, reported-only filtering, saved detail reloads, tracker status remaining Saved, export, fragment injection prevention, workspace clearing, consent/password behavior, genuine verification-pending state and owned onboarding progress. No existing test assertions were deleted or disabled. A new parser test's paragraph expectation was corrected to require the actual preserved blank lines; new selectors were scoped to their account panel and unauthenticated session assertions explicitly check absence of an identity.
