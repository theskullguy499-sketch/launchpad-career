Branch: `feat/launchpad-5-6-launch-readiness`. Base preservada: 5.5, commit `4e02d55` (238 testes anteriores). Nenhum merge, deploy, migração ou alteração de secrets/aprovações comerciais nesta entrega.

## Recuperação e correções

A execução interrompida deixou cinco arquivos modificados, sem commit, na branch 5.6. As alterações foram recuperadas e revisadas, sem reset nem descarte de trabalho.

1. **Corpos HTTP:** leitura incremental com limite real de bytes UTF-8, inclusive sem Content-Length. Requisições públicas/AI são limitadas a 12.000 bytes; JSON inválido/UTF-8 inválido e valores que não sejam objetos são recusados antes de quota/provedor. O fluxo de assinatura Paddle continua usando seus próprios bytes brutos e verificação criptográfica.
2. **Remotive:** resposta limitada a 8 MB; cache recente continua por 6 horas, fallback de falha/rate limit tem teto de 48 horas e é marcado `stale`. Datas futuras/inválidas não são reutilizadas. Favoritos e candidaturas não são apagados por indisponibilidade. Ausência no lote de até 100 vagas não comprova expiração; confirme o anúncio na fonte antes de se candidatar.
3. **Créditos:** contexto autorizado inválido é recusado antes de reservar quota. Saldo diário/mensal vem de `commercial_ai_allowance`, não de um limite diário fixo. Falha dessa consulta aparece como saldo desconhecido, sem inventar zero ou saldo positivo.
4. **Falhas de IA:** resposta do provedor limitada a 256 KB, prazo de chamada de 25 segundos preservado; erro/timeout/JSON inválido ou resposta inutilizável retorna erro explícito. Uma reserva já feita conta como tentativa, inclusive se o provedor falhar. Nenhuma repetição automática ou promessa de estorno. Detalhes privados do erro não são enviados ao cliente.
5. **Indicadores:** depois da chamada de IA, o Coach solicita atualização de Billing no servidor; não usa eventos do navegador para conceder planos. Guardas de identidade/geração existentes continuam impedindo respostas atrasadas entre contas.
6. **Artefatos:** novo `npm run audit:public`, também obrigatório em `npm test`, verifica allowlist, presença, hashes SHA-256, arquivos inesperados e padrões conhecidos de credenciais privadas/JWT de sessão. O relatório contém somente caminhos e categorias. Não substitui revisão de secrets arbitrários nem rotação de uma chave que já tenha vazado.
7. **Apresentação:** landing descreve Resume Studio e prática de entrevistas existentes e explicita dependências de serviços/checkout Sandbox. Marca, layout e navegação são preservados; sem números fictícios ou novos recursos grandes.

## Revisão das integrações existentes

- Auth usa SDK oficial, PKCE/token hash, `getUser` e confirmação pelo servidor. Callback remove credenciais da barra antes de validar e mantém destinos fixos; recuperação fictícia por query não autoriza reset. Sessão/refresh continuam sob Supabase, não senhas locais.
- Workspace usa usuário confirmado, RLS, owner/revision no commit e separação guest/account. Falha de carregamento bloqueia escrita na conta e preserva guest. Importação é explícita; currículo/prática têm consentimento separado. Backup JSON e exportação permanecem.
- Exclusão exige login recente, confirmação e verificação de billing; conta com assinatura pendente/ativa não pode ser apagada para escapar de cobrança. Dados visitantes no perfil do navegador são compartilhados por quem usa esse perfil.
- Jobs normaliza fonte, datas, descrições e URLs HTTPS sem credenciais. Filtros/paginação operam sobre o lote recebido; não é uma busca de todo o mercado. Conteúdo externo é renderizado como texto/estrutura segura.
- AI exige autenticação, idade, consentimentos e quota atômica no servidor. Sem provedor não há resposta gerada. Histórico só é salvo com consentimento. Quotas diárias/mensais/globais e limite de saída contêm volume; **não há garantia de teto rígido em dólares**. Configure orçamento/alertas no provedor e preços de tokens verificados; custos sem dados de tokens/tarifas continuam desconhecidos, nunca receita/margem inventada.
- Paddle verifica assinatura sobre bytes brutos, timestamp, evento idempotente e snapshots canônicos de transação/assinatura do provedor antes de atualizar acesso. `ntfsimevt_` autenticado só recebe ACK no Sandbox e não concede acesso; em produção é recusado. `evt_` mantém processamento real. Identidade, preços, cliente e assinatura continuam validados no backend.
- `verify_jwt=false` nas funções não significa ausência de segurança: handlers privados fazem `auth.getUser`; webhook exige HMAC; worker exige segredo próprio; jobs é público com cache/limite. Não alterar essas proteções para fazer testes passarem.

`PASS`: evidência executada para o escopo indicado. `FAIL`: verificação executada e reprovada. `NOT VERIFIED`: não testado no serviço real. `BLOCKED`: pré-requisito/decisão do proprietário impede avanço. Um PASS local não promove a linha remota.

|---|---|---|
| Dependências, build e SDK reproduzível | PASS | `npm ci`, `npm run build`, `npm run build:check` aprovados |
| Regressões browser, acessibilidade, backup/restore e contas simuladas | PASS | Chromium Linux; não prova entrega de e-mail |
| RLS/ownership/entitlements em PostgreSQL local | PASS | PGlite com migrações existentes; não deployment Supabase |
| Limites HTTP, IA/cache, HMAC/idempotência, isolamento em testes | PASS | Testes determinísticos; provedores simulados |

| Staging HTTPS/rotas publicadas | NOT VERIFIED | Proxy restrito; sem deploy nesta entrega |
| Cadastro, recebimento/confirmação/reenvio e recuperação em caixa postal | NOT VERIFIED | Exige contas/SMTP e caixa externa do proprietário |

| Respostas, créditos e custos de OpenAI reais | NOT VERIFIED | Sem binding, sem consumo autorizado aqui |
