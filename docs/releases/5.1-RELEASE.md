## Implemented — milestone B and C preparation

The existing complete official-SDK Auth and server billing lifecycle is retained.
Staging build variables populate **only the built** `_site/auth-config.js`.
`REQUIRE_PUBLIC_AUTH_CONFIG=true` now rejects missing public values; malformed,
partial or secret credentials are already rejected. A manifest boolean reports
whether public Auth configuration was supplied without copying private credentials.
The staging workflow requires configured public Auth. Portfolio builds can still
choose blank configuration and guest mode.

Build tests check public variable injection and unchanged committed config, plus
exclusion of SQL, backend source, docs and node_modules. Local static serving now
returns proper JPEG/PNG MIME types; production tests additionally assert SVG/JPEG
MIME and all manifest hashes. No deployed server or database was modified.

The owner chose to configure public values directly in Cloudflare. No values were
provided here, so B/C's real end-to-end acceptance is blocked on that configuration
and accessible authorized test accounts. The [runbook](5.1-STAGING.md) gives exact
Cloudflare/Supabase/Paddle settings and Windows CMD commands, plus the checklist
for the existing deployed backend. Existing API secrets alone do not enable a
purchase; additional legal/operator/environment/domain/flag gates remain.

## Integration truth and blockers

The owner reports a published staging URL and a correctly signed simulator receipt
with HTTP 200. This environment receives HTTP 403 when opening that staging URL,
and no Supabase project public values/test credentials were supplied. Therefore:

- Real account registration, confirmation/resend/recovery mail, private cross-device
  persistence and real two-account RLS tests: **not independently verified**.
- Real Paddle Sandbox purchase, canonical transaction/subscription, signed `evt_`
  processing, upgrade, renewal, cancellation, portal and failure lifecycle:
  **not verified against configured services**. A simulator receipt grants nothing.
- Real OpenAI/Remotive response delivery, usage reporting and licensing/terms
  review: **not independently verified**. Unconfigured UI remains explicit.
- Hosted CI, Cloudflare staging for this SHA, physical iOS/Android/Safari/Firefox
  and assistive technology acceptance: **not verified**. Local Chromium evidence
  cannot be represented as these checks.
- Operator/support identity, legal/billing/refund drafts, SMTP DNS, merchant/site
  approval, individual trademark permissions and live activation approvals remain
  owner-controlled gates. No compliance or guaranteed employment claim is made.

No external infrastructure changes or billable requests were performed. Actual
operating costs remain dependent on the owner's contracts/usage. Existing costs
and reconciliation instructions remain in the commercial operations runbook.
