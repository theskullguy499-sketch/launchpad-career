# Launchpad 5.5 — guia Windows CMD e Staging

Branch: `feat/launchpad-5-5-career-intelligence`. Base: 5.4 em `c5dd8bd`.
Nenhum merge, deploy, mudança de credenciais ou ativação de pagamentos faz parte desta entrega.

## 1. Atualizar com segurança

Primeiro exporte JSON de cada workspace que deseja preservar. Se houver alterações locais no código, guarde-as antes de trocar de branch; não use `reset --hard`.

Abra o CMD na pasta do projeto (Node 24 LTS):

```bat
cd launchpad-career
git fetch origin
git switch feat/launchpad-5-5-career-intelligence
git pull --ff-only
set PUBLIC_SUPABASE_URL=
set PUBLIC_PUBLISHABLE_KEY=
set REQUIRE_PUBLIC_AUTH_CONFIG=
npm ci
npx playwright install chromium
npm run build
npm run build:check
npm test
```

Os comandos `set ...=` limpam somente valores públicos nesta janela para testes determinísticos. Não alteram painéis remotos. Os testes não fazem cobranças e não enviam e-mails reais. O build padrão permanece funcional em modo visitante.

## 2. Gerar um NOVO build Staging

Depois dos testes, copie somente a chave pública publishable do Supabase para seu computador. Não envie service_role, sb_secret, senhas, SMTP, Paddle API/signing secrets ou chaves de IA ao frontend.

```bat
set PUBLIC_SUPABASE_URL=https://oyatshlhqdxosvbelsvp.supabase.co
set PUBLIC_PUBLISHABLE_KEY=COLE_AQUI_SOMENTE_A_CHAVE_PUBLICA
npm run build:staging
npm run build:check
```

`_site` é recriado pelo build. Confira `_site\build-manifest.json`: **80 arquivos públicos** e `publicAuthConfigured: true`. A versão em `package.json` deve ser `5.5.0-rc.1`. O código-fonte `auth-config.js` continua sem credenciais. Não reutilize `_site` antigo. Se executar a suíte novamente depois, gere o build Staging novamente antes de upload.

Direct Upload não injeta variáveis do painel em arquivos já gerados. A chave pública deve participar do build local. Nenhuma chave privada deve entrar na pasta publicada.

## 3. Publicação manual — somente quando aprovar

1. Revise branch, relatório e capturas.
2. Na Cloudflare, abra o projeto existente **launchpad-career-staging** → Deployments → Create deployment/Upload assets.
3. Envie o conteúdo de `_site` como raiz; `index.html` precisa ficar na raiz publicada. Não envie repositório, SQL, `.env`, testes ou `node_modules`.
4. Use o projeto/URL existente `https://launchpad-career-staging.pages.dev/`. Não crie outro projeto nem publique no domínio comercial.
5. Verifique os módulos novos e Auth no navegador, usando seus próprios dados e contas de teste.
6. Atualizar a mesma URL Staging mantém o armazenamento local daquela origem. Localhost, GitHub Pages e outro domínio têm armazenamento separado; use exportação/importação JSON explícita para transferir material visitante.
7. Para rollback do frontend, use o deployment anterior na Cloudflare. Não reverta tabelas nem apague dados. Preserve backups.

**Não há migração adicional nem nova Edge Function na 5.5.** Não reexecute migrações existentes. As descrições completas de vagas continuam dependendo da atualização de `job-explorer` herdada da 5.3, caso o proprietário ainda não a tenha publicado: [guia anterior](5.3-STAGING.md).

O workflow separado do GitHub Pages continua exigindo execução manual em `main` com `deploy=true`. Esta branch não satisfaz a condição de deploy. Não use esse fluxo para publicar Cloudflare Staging.

## 4. Testar os recursos novos

### Resume Studio

1. Entre em modo visitante → Resume Studio.
2. Preencha nome, headline, contato opcional, habilidades e idiomas.
3. Adicione somente formação/experiência reais. Projetos pessoais, como seu Launchpad ou FinanceFlow Pro, devem ficar em Portfolio projects, sem apresentá-los como empregos.
4. Observe a prévia, selecione Classic/Modern e clique Save version.
5. Se digitar enquanto Save estiver aguardando a nuvem, a resposta não substitui as novas edições. A mensagem informa que elas ainda não foram salvas; clique Save novamente para persistir o rascunho atual.
6. Duplique uma versão, altere seu nome e salve. Recarregue para conferir persistência.
7. Use Print / Save PDF e escolha o destino PDF do navegador. Revise páginas, margens e dados antes de compartilhar.
8. Exporte JSON em Settings → Data & Export. O backup inclui as versões salvas, não alterações ainda não salvas.

### Interview Lab

1. Escolha um tópico/pergunta: todo o banco é material estático de prática.
2. Escreva sua própria resposta em inglês e use o cronômetro se quiser.
3. Salve o exercício, confira histórico, abra/edite e salve novamente.
4. Marque e salve a checklist. Recarregue para conferir.
5. Review in AI Coach pede confirmação e apenas prepara o prompt. Revise o conteúdo e consentimentos no Coach antes de Ask coach. Sem backend e créditos não existe avaliação por IA.

### Conta e privacidade

1. Faça login em conta confirmada e aguarde o workspace privado carregar.
2. Os dados visitantes não devem aparecer automaticamente. Para salvar currículo/exercício, aceite o controle explícito de salvamento no Supabase.
3. Em Resume Studio, Import guest career material exige consentimento e confirmação. A importação é separada da importação genérica antiga; versões com o mesmo ID não duplicam e a versão já existente na conta prevalece.
4. Cloud sync continua sujeito aos direitos de assinatura e configuração comercial do servidor. Consentimento não concede Pro/Premium.
5. Saia e entre em outra conta: prévia, respostas, resultados da busca e nós de impressão privados devem ser limpos. Faça também a verificação em outro dispositivo.

### Job Fit, Dashboard e busca

Pesquise vagas reais somente quando o backend estiver configurado. Nos detalhes, compare palavras citadas na fonte com suas habilidades declaradas em currículos salvos e metas. Informações ausentes devem permanecer indisponíveis. Localização não comprova autorização de trabalho. O botão de candidatura continua abrindo a fonte oficial, sem envio automático.

Use Ctrl+K (Windows/Linux), Cmd+K (macOS) ou Search. Pesquise páginas, candidaturas, favoritos, metas e nomes de versões. Setas navegam resultados, Enter seleciona e Escape fecha, inclusive com pesquisa preenchida. Add application/Create career goal abrem os formulários existentes.

No Dashboard, confira contagens de currículos/exercícios/bookmarks, próxima entrevista/prazo e a origem da recomendação. Não são métricas ou avaliações externas.

## 5. Limites que importam

- Até 5 versões, 8 entradas por seção e 30 exercícios, **sempre dentro de 45.000 bytes de preferências serializadas compartilhadas**. Favoritos de vagas e outras preferências usam o mesmo orçamento. O limite remoto herdado é 50 KB de JSONB e o workspace total permanece limitado a 2 MB; falhas são explícitas, sem excluir material automaticamente.
- Respostas de prática: até 2.000 caracteres. Histórico de perguntas usa IDs estáveis do banco de prática; não altere o significado de um ID em versões futuras.
- Rascunhos são mantidos somente em memória até Save. Não contam como backup ou sincronização. Troca de conta limpa os rascunhos por privacidade.
- Modo visitante é compartilhado pelo perfil do navegador. Não é isolamento entre pessoas usando o mesmo perfil.
- PDF usa o diálogo do navegador; Safari/Firefox, dispositivos físicos e todos os parsers ATS ainda precisam de revisão. Não existe certificação ATS universal.
